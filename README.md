# RetailFlow — Databricks Data Engineering CI/CD

A hands-on portfolio project demonstrating PySpark transformations, data quality checks, Databricks Spark Declarative Pipelines, Unity Catalog, Databricks Declarative Automation Bundles, and GitHub Actions.

## Architecture

```text
Unity Catalog Bronze tables
  ├── customers
  └── orders
       │
       ▼
Spark Declarative Pipeline (PySpark)
  ├── customers_clean           [Silver]
  ├── orders_clean              [Silver]
  └── customer_sales_summary    [Gold / business summary]

Git feature branch → pull request → GitHub Actions CI
main branch → GitHub Actions CD → Databricks bundle deploy (prod)
```

The project uses **one Databricks Free Edition workspace** with separate Unity Catalog catalogs for environment isolation. These are logical DEV, TEST and PROD environments, not three independent workspaces.

## Environment configuration

The bundle is designed to parameterize the Unity Catalog name and source table names through `catalog_name`, `customers_table`, and `orders_table`. The pipeline reads those settings from its `configuration` map.

- DEV catalog: `retailflow_dev`
- TEST catalog: `retailflow_test`
- PROD catalog: `retailflow_prod`

Source datasets are pre-existing Unity Catalog Bronze tables. Bundle deployment does **not** seed the data.

## CI/CD behavior

**CI** (`.github/workflows/ci.yml`) currently runs checkout and a basic confirmation step on PRs targeting `main` and on pushes to the specified feature branch. **It does not yet execute pytest or validate the bundle.** Native pipeline tests were run manually earlier in the project; automated test execution remains an improvement opportunity.

**CD** (`.github/workflows/cd.yml`) triggers on pushes to `main` and via manual dispatch. It installs the Databricks CLI, runs `databricks bundle validate -t prod`, then `databricks bundle deploy -t prod`. The GitHub Actions deployment was observed succeeding. **Deployment is not the same as executing the data pipeline**; pipeline runs were checked separately in Databricks.

The workflow uses the repository variable `DATABRICKS_HOST` and the GitHub Actions secret `DATABRICKS_TOKEN`. Never commit tokens or other credentials to source control.

## Scope

This repository is an educational portfolio demonstration. Its three catalogs and successful example runs show environment-specific processing, but do not by themselves establish enterprise production readiness.
